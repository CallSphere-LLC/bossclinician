# Voice, permissions, sessions and native calls

Verified against K3 preview release `20260919182846-f736b5f` on 2026-09-19. The browser retained the real public/admin origins through a local streaming TLS proxy; no response payloads were fabricated. Production cutover verification is recorded separately when complete.

- `routes.json`: 64 authenticated destination pages (50 admin, 14 member), actual fresh logins, no unexpected redirects, JavaScript errors or non-401 API failures. The media library required a streaming proxy: the earlier Playwright response-buffering shim exceeded Chromium's 100 MB DevTools message limit when serving a video; this was a harness limitation.
- `role-permission-checks.json`: 17 checks covering anonymous forged-admin demotion, member/admin admission, unsupported role catalog rejection, SUPPORT owner-only conversations denial, cross-user transcript/recording denial, and persisted member/admin tour position. These initially ran on the earlier staged release; the privacy regression below was repeated after its fix.
- `inbox-privacy-before.json` and `inbox-privacy-after.json`: SUPPORT could originally read existing admin/member legacy inbox conversations. After the fix both detail requests return 404 and the list excludes private rows. New private conversations are no longer mirrored to the public visitor inbox.
- `auth-refresh-after.json`: an admin request with its access cookie removed receives 401, refreshes through `/admin/refresh` (204), retries successfully (200), and retains the admin surface. A member request with an invalid bearer receives 401, refreshes through `/auth/refresh` (200), retries successfully and retains the member surface.
- `auth-timeout.json`: isolated real sessions have 28,800-second admin and 2,592,000-second member absolute deadlines. Refresh preserves each exact stored deadline. After advancing only those fixture session deadlines into the past, refresh returns 401 and a protected page reload redirects to the matching login page. This simulates deadline expiry; it does not claim an eight-hour or thirty-day wall-clock soak.
- `lead-decline-reapprove.json`: declining preserves the fixture enquiry's `new` state. A new proposal after the decline receives click approval as `lead.status#2`; its tool output confirms execution and a separate API read verifies the persisted `contacted` state. No stale approval is reused.
- `native-call-history.json`: two distinct signed-in members join the same native community room. Each browser receives local and remote video frames (640×480, readyState 4), with live audio/video tracks and a visible elapsed timer. Both explicitly leave. Reloaded personal history displays the persisted ending timestamps and 8-second/6-second durations. No JavaScript errors occurred. These are the native community calls, separate from the AI concierge's provider calls.

Latest complete local unit runs: frontend 361 tests in 36 files; backend 1,214 tests in 92 files. Database suites are opt-in and were skipped in the ordinary backend run. The K3 agent separately ran 285 real database tests and repeated the final native-history suite (17 tests); use its final test report for the combined database total. Both TypeScript checks passed. Focused coverage includes admin JSON request headers, binary recording header preservation through refresh, schema retention when catalog discovery also reads records, live-recording 409 behavior, and real database end-session ownership/idempotence. The final contract regression also proves that original tool arguments survive the browser wire and Responses function-call reconstruction; replacing them with empty objects was found to cause repeated catalog discovery. Numeric positive safe record IDs are normalized to strings before preparation; tests reject fractional, nonfinite and unsafe values while preserving page slugs.

QA identities and communities are disposable, use a `release-20260919-qa` prefix, and are tracked in private `/tmp` fixture files for coordinated cleanup. No credentials or production customer messages are stored in this evidence file.

## Direct production verification

After public `/api/health` confirmed release `20260919183929-f736b5f`, the following browser checks ran against the real HTTPS hosts, with no preview proxy or request overrides:

- `production-native-call-history.json`: two distinct members each received local/remote live audio/video tracks and 640×480 frames. Elapsed time continued in the floating call on `/library`; its return link restored the room. Both calls explicitly ended, and personal call history survived reload.
- `production-inbox-privacy.json`: SUPPORT receives 404 for both existing privileged concierge conversations; the public visitor inbox returns 200 with no private session IDs.
- `production-admin-voice.json`: actual synthesized speech requested enquiry 22 change from `contacted` to `new`. The admin clicked the real approval card, a separate API read confirmed persistence, the execution audit returned 200, nine recording chunks were accepted, `session.closed` arrived, and `/voice/end` returned 200. A database read confirmed a durable ending timestamp. No browser JavaScript errors occurred.
- `production-member-voice.json`: actual synthesized speech navigated from the library to `/account`; spoken output, recording/transcript writes, `session.closed`, and `/voice/end` 200 were observed without JavaScript errors.
- `native-fixture-cleanup.json`: the temporary native community and second member were deleted after both testing lanes finished. Database readback found zero remaining native visits or member sessions for those fixtures. The root agent owns cleanup of its primary QA accounts and all voice recordings/conversations.

The native test's first production run used a button selector for a return **link**; its corrected run completed. The first spoken admin harness closed its browser after a fixed six-second pause, before the recording/end sequence had completed; the successful rerun waited for the actual `/voice/end` response. These intermediate harness attempts are not counted as successful complete calls. Their temporary voice IDs were handed to the root cleanup list.
