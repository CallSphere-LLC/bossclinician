## Confirmed gaps, distinguished from formula defects

1. **Numeric validation bug fixed:** previously restored `capCurrentUtil=-20`, scenario 85 and revenue 50,000 produced **−212,500** modeled revenue; `cashExpenses=-100`, cash 30,000 produced **−300 months** runway and a **−300** reserve target. `normaliseBoardroom` now rejects nonfinite, wrong-type, negative and explicitly over-max numeric values to the existing field default (usually null; guardrails 15/85 and reserve months 3). It does not clamp to zero or 100. Null remains an intentional blank; absent values retain defaults. All input fields have min=0; only `guardrailPct`, `capGuardrail`, `capCurrentUtil`, `scenarioUtil`, `splitPct` have max=100. Hiring utilization above 100 and fractional counts remain permitted, matching the existing UI. Scenario fields were checked: all are labeled Additional/Extra with min=0, so negative inputs are invalid; computed losses and owner-pay reductions remain signed. Regressions prove rejected negative cash expenses use existing COGS/opex fallback (**40,000 outflow, 0.75 months runway, 120,000 reserve**) or missing results without base costs. Negative current utilization gives missing modeled revenue without capacity data, or the existing fallback (**53,125**) with 80% derived utilization. Parent state setters now normalize fresh inputs and the Boardroom-local wrapper uses the shared helper with visible per-field errors; shared DashboardKit is untouched. Calculation helpers themselves continue to expect normalized state.
2. **Partial-input ambiguity, unchanged:** entering only revenue 50,000 produces profit **50,000 / 100% margin** because blank costs become zero. Entering the hiring example's target/rate/cost/overhead and only steady utilization 85 treats blank months 1–3 as zero utilization: cumulative loss **22,500**, breakeven **month 12**. This conflicts with a literal “show missing” interpretation of the integration spec. Ask the owner which inputs are required versus optional before changing established assumptions. Similar zero-fill applies to missing wage hours, optional employer/benefit components and scenario deltas.
3. **Feature boundaries:** pay-method and clinical-role selectors are informational, not alternate formulas. Capacity period/group/method selects labels and interpretation, not automatic conversion. These are verified implementation limitations, not evidence that the arithmetic should be replaced. Supplied HTML payroll ratio, revenue/clinician and target gaps are separate legacy calculations absent from the current nine-tab functions; row 186 does not authorize adding duplicate inputs or rebuilding those views.
